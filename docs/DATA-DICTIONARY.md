# 统一清算席数据字典

## 来源文件

| 字段 | 定义 |
|---|---|
| 竞价场次 | 文本主键，保留前导零。跨业务键不汇并记录。 |
| 修订号 | 正整数。最高版优先；最高同版字段冲突或存在同版、更新版的未采信记录时隔离，旧版无法接替。 |
| 提交时间 | ISO 8601，必须带 UTC 偏移量。标准化后展示 UTC。 |
| 原始备注 | 可空，允许引号内换行。 |
| 可售数量、底价元、报价事件 | 必填字段。多项字段用半角分号隔开，显式空集合用 `无`。 |

识别 `UTF-8`、UTF-8 BOM 与独立的 `GB18030` 文件。`业务编号`、`版本`、`更新时刻`、`备注` 为旧版表头别名。新旧名同时出现会被拒绝。`-`、`N/A`、`NULL`、`未知` 和空串均按必填值缺失处理。物理行号指 CSV 逻辑记录起始行。

## 计算字段

报价事件写 `买家:修订序号:到达时点:报价元:数量`。每位买家只采信最高修订，数量为零表示撤单。

价高优先，同价按时间、买家编号排序。全部售出时以最低获配价清算，未售完按底价清算所有已配数量。

数值在服务端以十进制定点方式计算，对外按字符串传输。单文件上限 128 KiB，复合字段最多 240 个项目，个别字段还有业务上限。格式无法恢复的 CSV 整批拒绝，列数、缺字段、来源冲突和业务条件错误逐条隔离。

## 复算与外部清单

外部清单包含 `竞价场次` 和 `外部记录值(元)`，允许省略不在对账范围内的键。同一键重复会拒绝该清单。结果数值单位为 **元**。差值按本次复算减外部记录，缺一侧时差值计算以 0 占位并保留缺失原因。

同一对输入字节与规则版本生成同一批次，导出包含两个文件摘要、证据行、单边差异和复核修订记录。复核保存前检查当前版本，在有隔离、差异或退回时必须填写意见。

## 晚到更正与冲销单

批次经「确认」签核后，历史结果与签核记录即冻结；报单填错只能由结算员登记晚到更正，由工作台另出冲销单，不改写原批次。

登记接口 `POST /api/corrections/{run_id}` 接收目标 `竞价场次`、更正原因、更正后完整来源 CSV，以及可选外账（缺省沿用批次保存的独立账）。服务端对更正后来源重跑同一管线并做影响划界：

- 仅目标场次的金额、统一清算价与买家获配允许变化；其余场次（同期别来源）的金额与清算依据、以及全部隔离/抑制来源行必须逐行一致，否则返回 `CORRECTION_SCOPE`。
- 目标场次更正后无法清算返回 `CORRECTION_INVALID`；与原签核完全一致返回 `CORRECTION_NOCHANGE`。
- 未签核确认的批次返回 `CORRECTION_REVIEW`；更正原因必填。

冲销单逐场给出 `old_amount`、`new_amount`、`reversal_amount`（更正后减原签核，可为负）、统一清算价前后值与差额、同场各买家获配数量前后值与差额，并附原签核清算依据 `old_proof` 与更正后 `new_proof`。`scope.unchanged_sessions` 明示哪些同期别场次不计入本次冲销。

外账核对分两段留痕：登记时按当时外账分别核对原签核金额与更正后金额；发布接口 `POST /api/correction/{id}/publish` 用最新外账按场重核**更正后金额**，全部 `MATCH` 才能发布。未通过返回 `VOUCHER_BLOCKED`，冲销单保持待发布，补账后可对同一更正重试。被拒的重核不落库。

更正编号为 `sha256(规则版本:correction:批次:来源摘要:外账摘要)`，表上对 `(run_id, source_sha256, book_sha256)` 加唯一约束：同一更正（含并发）重试只回送既有冲销单，换外账则视为另一笔更正。整笔写入在单事务内完成，失败回滚，`runs`/`reviews` 不受影响；原签核金额、依据与复核时间线内嵌在冲销单 `original_review`、`old_proof` 中，导出证据包另附该批次的更正清单。
